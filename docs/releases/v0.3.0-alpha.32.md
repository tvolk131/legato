This alpha adds a diagnostic for unexplained switches back to the Mac. It is also the first upgrade between two Developer ID signed Mac apps.

The protocol is unchanged (13), so alpha.30 and alpha.31 can still connect. For testing, install alpha.32 on both machines.

- **MacBook (Apple silicon):** `legato-v0.3.0-alpha.32-macos-arm64.tar.gz` → `Legato.app`.
- **RTX 3070 Windows PC:** `legato-v0.3.0-alpha.32-windows-x64.zip` → `Legato.exe`.
- Windows ARM PCs use `legato-v0.3.0-alpha.32-windows-arm64.zip`.

Quit Legato from its menu/tray before replacing it. Alpha.31 and alpha.32 are signed with the same Developer ID, so Accessibility, Input Monitoring and Screen Recording should be kept. Please report whether they were: this hasn't been confirmed on real hardware yet. Settings, pairings and the device identity are kept.

## Diagnostics

- **Why the Mac took control back.** While the Windows PC drives the Mac, any input on the Mac that didn't come from Legato makes the Mac take control back. That includes input other programs post. The log line now names the event and the program macOS says sent it:

  ```
  input that didn't come from a peer was seen on this machine (a key, button or scroll: key down, source pid 2741 (Wispr Flow), source state 0): taking back control
  ```

  The process ID and source state are macOS's raw values. Which values the Mac's own keyboard and trackpad produce hasn't been checked yet.

## Testing the Slack screen-share problem

Input from Windows to the Mac's extra display can misbehave while that display is shared from Slack on the Mac. To find the cause:

1. Share the extra display in a Slack huddle.
2. Drive it only from Windows, without touching the MacBook, until input misbehaves.
3. In `~/Library/Application Support/io.github.tvolk131.Legato/legato-app.log`, find the `taking back control` lines and note the program each one names.
