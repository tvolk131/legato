# 0.3.0 release plan

Readiness review: November 5, 2026, starting at main `3e46cd3`. The next step is
a signed release candidate and checks on the real Mac/Windows pair. Signing is
working; the application is not yet verified for a final 0.3.0 release.

## Scope and evidence

Keep the existing scope: macOS 26+ on Apple silicon and Windows 11 on x64 and
ARM64; shared input, clipboard, files, and a Mac display in the Windows viewer.
Both machines should run the same candidate. The current wire protocol is 13.
Finder drag-out, custom cursor images, Windows secure-desktop control, and a
Windows display streamed to Mac are outside this release's scope.

- All five CI checks passed on the signing PR's final head `20d507c`, including
  workspace Clippy/tests on Mac and both Windows architectures, hosted platform
  tests, and the Rust 1.99 check.
- [Signing test 42073110433](https://github.com/tvolk131/legato/actions/runs/42073110433)
  built the existing `v0.3.0-alpha.30` source (`33c2778`) with the new workflow.
  Apple accepted the app and CLI without reported issues. Stapling, signatures,
  and Gatekeeper assessment passed after extracting the final Mac archive.
- That test proves the signing path, not the latest application build: the
  iced-m3 beta.6/icon changes in `417e161` still need a signed candidate. It also
  does not establish permission retention or physical GPU/input behavior.

The broader [testing strategy](../../TESTING.md) includes future test-harness
ideas and a larger hardware matrix. Use the focused gates below for 0.3.0;
record the machines and results rather than assuming every planned test exists.

## Prepare the first candidate

- [ ] Merge the release preparation changes: stable tags create regular GitHub
  releases, suffixed tags remain prereleases, every workspace package version
  must match the tag, and pushes to `release/**` run CI.
- [ ] Cut `release/0.3` from the selected green main commit for the first release
  candidate. Keep it to release fixes and documentation; bring applicable fixes
  back to main. Use PRs and require passing checks for every change.
- [ ] Set `[workspace.package].version` and all workspace entries in `Cargo.lock`
  to `0.3.0-rc.1` without updating unrelated dependencies. Add candidate notes
  describing supported features, installation/permissions, and known limits.
- [ ] After that exact commit passes CI, tag it `v0.3.0-rc.1`. The tag workflow
  builds all three packages, signs/notarizes the Mac app and CLI, and publishes
  a GitHub prerelease only after all platform packages succeed.
- [ ] Inspect the actual downloads: correct versions, architectures, bundled
  Material Symbols license/notice, and the Mac notarization diagnostics. Test
  the downloaded candidate, not a local development build.

## Hardware gates before final

All rows start **pending**. Record candidate, OS, machine, steps, result, and log
location for each run. Hosted CI does not substitute for these observations.

| Area | Required evidence |
| --- | --- |
| Signed install and permissions | Launch the downloaded Mac candidate from its intended installation path, grant required permissions, and verify input sharing and screen capture. Also check a fresh user or clean machine so existing grants do not hide first-run problems. Quit/relaunch and test launch at login. |
| Signed upgrade | Upgrade from one signed candidate to a second signed build at the same path, with the same bundle ID and signing team. Verify Accessibility, Input Monitoring, Screen Recording, Local Network access, pairing, settings, and launch at login. An initial ad-hoc-to-Developer-ID permission reset is separate from this test. |
| Input and recovery | Test both directions and both control policies on the real monitor arrangement. Cover the Windows mouse and Mac trackpad, pointer continuity, modifiers/default Alt/Win mapping, Caps Lock, clicks, scrolling, and dragging. Disconnect, quit, sleep/wake, lock/unlock, and change networks without leaving stuck keys or losing local control. |
| Clipboard and files | Transfer text, an image, files, and a nested folder with an empty directory in both directions. Check name collisions and an interrupted transfer; existing files must survive and failures must be visible. Exercise both Send files and the supported Windows edge drag. |
| Extra Mac display | Repeatedly select 1080p and Retina 4K through the Windows options, close/reopen the viewer, change quality, use F11 full screen, and move between the viewer and physical monitors. Check cursor shapes with the Windows mouse and Mac trackpad, colors/text, and sustained motion. Save the backend line and F10/decode timings. Software fallback is allowed; do not claim hardware decoding or a speedup without physical-GPU evidence. |
| Connectivity and ordinary use | Pair on the LAN, quit/reopen, and reconnect on different networks using the saved pairing. Use the candidate for a normal work session, including a larger file transfer while controlling the other machine. Record Windows x64 versus ARM64 hardware coverage; hosted ARM64 checks alone are not a physical-device pass. |

Detailed sequences are in [TESTING.md](../../TESTING.md), including display-mode,
cursor, decoder, file-transfer, and recovery checks. Signing setup and its limits
are in [macos-signing.md](../macos-signing.md).

## Known reports to resolve or explicitly accept

- **Windows wake crash:** older logs show DX12 `ResizeBuffers`/`E_OUTOFMEMORY`.
  Restart resilience was added, but the underlying cause was not established.
  Repeat sleep/wake on the candidate, including with the viewer open. A repeated
  crash or loss of local input blocks final release; collect the preserved log.
- **4K mode selection:** the reported persistent 1080p result after choosing 4K
  has not been verified fixed through the actual Windows options. The synthetic
  mode-recovery test is not a reproduction of that app sequence. Record the
  requested and actual point/pixel size after repeated changes and reopening.
- **Windows main-window resize wobble:** remains unresolved after the unverified
  graphics fork was removed. Compare current Mailbox and FIFO presentation using
  the documented sequence. If it is cosmetic and resizing/input remain usable,
  it may be a documented known issue; rendering failures or lost controls block
  release. Do not change the default presentation mode without PC evidence.

These are outstanding validation questions, not claims that every old report
still reproduces. The signing problem and cursor-shape implementation have moved
on since the historical handoff; do not reopen completed work from that snapshot.

## Final release

- [ ] Resolve blocking failures through PRs and rerun the affected hardware
  sequences. Keep lower-priority limitations explicit in release notes.
- [ ] Test at least two signed candidate builds for the upgrade gate and use
  the final candidate in an ordinary work session without a blocking regression.
- [ ] Prepare the `0.3.0` version/lockfile update, final release notes, and README
  status/install guidance on `release/0.3`; confirm the exact final commit passes CI.
- [ ] Push `v0.3.0` only when ready to publish. The unsuffixed tag creates a
  regular GitHub release after all packages and Apple validation succeed.
- [ ] Verify the published asset inventory, digests, embedded versions, Mac
  identity/ticket, and download launch. Retain test evidence and bring release
  fixes/version documentation back to main.

Creating the release branch or approving the workflow does not mark these gates
complete. No final release is authorized by this checklist alone.
