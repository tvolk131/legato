This alpha fixes the Mac app quitting as soon as it opens. Every SwiftUI Mac build since alpha.31 crashed this way as soon as Legato started up. Otherwise it's the same as alpha.33, including key mappings and the Mac fn (Globe) key.

The protocol is unchanged (13). The Windows app has no changes besides the version number, so a PC on alpha.33 can stay on it.

- **MacBook (Apple silicon):** `legato-v0.3.0-alpha.34-macos-arm64.tar.gz` → `Legato.app`.
- **RTX 3070 Windows PC:** `legato-v0.3.0-alpha.34-windows-x64.zip` → `Legato.exe` (optional).
- Windows ARM PCs use `legato-v0.3.0-alpha.34-windows-arm64.zip`.

Quit Legato before replacing it. The Mac app is signed with the same Developer ID as before, so Accessibility, Input Monitoring and Screen Recording should be kept. If the Mac app you used before alpha.31 had a different bundle ID, macOS may ask for them again. Settings, pairings and the device identity are kept.

## Fixed

- **The Mac app no longer quits on launch.** The engine's change notification was tied to the app's main thread, and Swift stops the app when the engine sends it from another thread, which it first did while starting up. The notification can now arrive on any thread.

## Please test

1. Open Legato on the Mac and check that it stays open, shows the PC as connected, and that the keyboard and mouse cross over as before.
2. The alpha.33 tests: on the PC, map Right Ctrl to fn (Globe) on Macs, then hold it with the pointer on the Mac and check that Wispr Flow starts and stops listening. Also report whether the PC keeps control after Wispr Flow types its transcription.
