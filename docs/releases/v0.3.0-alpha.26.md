The Mac now encodes the newest available picture to prevent a capture backlog, with timing logs to check the effect on streaming latency.

## Changed
- **Capture no longer waits for encoding.** Previously the Mac encoded each picture in the capture callback. At full 4K, encoding takes nearly the whole frame's time, which can leave captured pictures waiting. That is the suspected cause of the F10 overlay's "Mac 84" reading. Capture now hands pictures to a separate encoder thread through one slot: a waiting picture is replaced when a newer one arrives.
- **The Mac logs where the time goes** while showing its extra display, every 5 seconds: how long pictures took to be captured, waited for the encoder, and took to encode, and how many were skipped.

## Validation
The encoder stress test passes on macOS CI: when pictures arrive faster than they can be encoded, waiting pictures are replaced and latency stays bounded. The change still needs a real Sharpest 4K session with motion, comparing the F10 overlay and the Mac's new timing logs. The latency improvement and resulting frame rate have not yet been measured on that setup.

## Updating
Only the Mac needs this version: it still connects to 0.3.0-alpha.23 and later.

On the Mac, quit Legato, install the new version, then run:
```sh
xattr -dr com.apple.quarantine /Applications/Legato.app
tccutil reset Accessibility io.github.tvolk131.legato
tccutil reset ListenEvent io.github.tvolk131.legato
tccutil reset ScreenCapture io.github.tvolk131.legato
```
Then open Legato and allow the prompts.
