Windows now tries GPU H.264 decoding when showing the Mac's extra display, with an automatic software fallback.

## Changed
- The decoder uses a D3D11 video device and checks a known Mac-encoded color sequence before enabling it. The Windows log names the GPU used for the live stream, or explains why hardware decoding was unavailable.
- A decoding or device failure requests a fresh keyframe and switches that track to software until the display session is restarted.
- Decoded GPU pictures are copied back into the existing viewer format. F10's decode timing includes that readback; the renderer and wire protocol are unchanged.

## Validation
Tests cover the committed Mac video sequence, forced software decoding, recovery from a fresh keyframe, padded picture layouts, and D3D11 texture readback on Windows' WARP renderer. Actual hardware H.264 decoding and the performance improvement still need confirmation on a physical Windows GPU.

For the first check, use Sharpest at 4K with sustained scrolling or window movement. Look for `H.264 decoding: D3D11 hardware on ... (NV12 readback)` in the Windows log, and compare F10's decode time with the previous roughly 13–15 ms. Also check adaptive quality, resizing, and sleep/wake. If hardware fails, keep the fallback reason from the log.

## Updating
Only Windows needs this update. The Mac can stay on alpha.26, and protocol 10 remains compatible with alpha.23 and later. Quit Legato on Windows, extract the new Windows package, and run its `Legato.exe`.
